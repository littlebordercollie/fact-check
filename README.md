# fact-check

> 一个发布前的事实核查 skill。读一段文字，把可疑的地方插上记号，然后**把判断权还给你**——它一个字都不替你改。

写公众号、博客、newsletter、社媒长文……观点在脑子里都通，一落到字上就开始漏：年份记串、前后打架、举的例子其实撑不住论点。靠自己回头检查又不太行——当局者迷，而且写到大半夜脑子是糊的。

这个 skill 就是请来替你过一遍的那个“判官”：不困、不偏心、也不给你留面子。但它只标记、不动手，稿子还是你的。

## 它做什么

读一段文字，从两个层面核查：

- **离线层**（不联网，快）：抽取可证伪的客观断言，自查四类问题
  - 🚩 事实错误（年份/数字/人名/术语）
  - ⚠️ 逻辑跳跃（把相关当因果、藏前提）
  - 🔁 前后矛盾（同篇自相打脸）
  - 💥 点塌（例子/比喻撑不住论点——最难抓、最值钱）
- **联网层**（只查筛出来的那几条）：对时效性强、自己没把握的断言上网查证，给 ✅成立 / ❌反驳 / ⚠️查不到 / 🔀有争议，**必带来源链接**

## 三条铁律

1. **只标记，不改写**——判断权永远在作者手里
2. **宁可多标，不可漏标**——误标几秒就放过，漏标是发出去才脸红
3. **给证据，不替你裁决**——来源打架时如实摆两边，不假装有标准答案

## 它标什么、不标什么

最常见的疑问是“我主观的观点它会不会也标”。分两层：

- **你的观点本身，它不碰**——立场、好恶是作者的自由（“我觉得这个最好用”不可证伪，不标）
- **但你推向观点的逻辑和例子，它会查**——论证链断了、例子撑不住，会标（⚠️/💥）

一句话：**结论你做主，但通往结论的逻辑塌了，它会拽你一把。** 它不是来跟你的观点对线的，是来看你这观点站得稳不稳的。

## 安装

把这个仓库放进你的 skills 目录：

```bash
# Claude Code（用户级，全局可用）
git clone https://github.com/<your-name>/fact-check ~/.claude/skills/fact-check

# 或项目级
git clone https://github.com/<your-name>/fact-check .claude/skills/fact-check
```

重启会话后，对 Claude 说“帮我核查一下这段”或“发布前事实核查”即可触发。

> 也兼容其他读取 `SKILL.md` 约定的 agent 环境（Codex、OpenCode 等），把目录放到对应的 skills 路径下即可。

## 用法

```
你：帮我事实核查一下这段 —— [贴上你的文字]
```

它会输出一份核查报告，逐条标记 + 联网查证结果 + 来源链接，最后一句永远是“以上只是标记，改不改你定”。

## 可移植性

默认用标准 `WebSearch` / `WebFetch`，**任何 Claude 环境开箱即用，不依赖任何私有浏览器插件**。如果你装了更强的抓取工具（CDP 浏览器之类），可以在联网层替换它来对付登录墙/反爬页面——但这不是必需的。

## 设计哲学

**它是镜子，不是裁判。**

事实核查最容易跑偏的地方是越权——从“提醒你这儿可能不对”滑成“我帮你改对了”。一旦它替你改，你就把判断权交出去了。所以它宁可啰嗦地多标几个“存疑”，也不替你拍一次板。

久了你会发现，它真正训练的不是稿子，是你自己对事实的那根弦。
